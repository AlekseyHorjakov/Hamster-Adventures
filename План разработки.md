# План разработки и обучения — Hamster Adventures

> Статусы: **Запланировано** — ещё не начато; **В работе** — выполняется; **Реализовано** — сделано, но проверка не завершена; **Проверено** — результат проверен по критериям этапа.
>
> План основан на согласованной концепции из [README.md](README.md). Детали, которые пока не определены, не считаются утверждёнными требованиями. Порядок этапов меняется только после обсуждения технической причины.

## Цель

Постепенно создать играбельный Windows-прототип, затем расширить его до полной 2D-игры с локальным кооперативом для двух игроков, платформингом, beat ’em up, боссами, лагерем, профилями и сохранениями. Обучение идёт параллельно: каждую тему изучаем непосредственно перед её применением.

## Правила прохождения этапов

1. Перед этапом проверяем связанные требования README, текущее состояние проекта и зависимости.
2. За один рабочий шаг выполняем одну логически завершённую задачу.
3. Для каждой задачи фиксируем ожидаемый результат и критерии проверки.
4. Не отмечаем задачу как «Проверено», пока результат не проверен в Unity или подходящим тестом.
5. После существенных изменений обновляем этот план и дневник разработки.
6. Сначала делаем минимальную рабочую версию механики, затем улучшаем её. Не создаём все уровни и контент заранее.
7. Не меняем утверждённый визуальный канон персонажей и архитектуру без объяснения причины и согласования.

## Этапы

### Этап 0. Проверка исходного состояния и организация проекта
**Статус: В работе**

**Что делаем**
- Проверяем установленную версию Unity, целевую платформу, структуру проекта и наличие сцен, скриптов и ресурсов.
- Проверяем настройки проекта, используемый Input System и систему контроля версий, не меняя их без необходимости.
- Сопоставляем фактические файлы с README и отмечаем уже существующую работу.
- Создаём резервную точку/коммит перед крупными изменениями, если Git доступен.

**Чему учимся**
- Что такое проект Unity, сцена, папка Assets, Inspector, Hierarchy, Project и Console.
- Как безопасно сохранять изменения и читать ошибки.

**Критерии завершения**
- Известны версия Unity, структура проекта и фактическая стартовая сцена.
- Понятно, что уже существует и чего действительно не хватает.
- Зафиксированы важные технические ограничения.

### Этап 1. Минимальная игровая сцена и основы Unity
**Статус: В работе**

**Что делаем**
- Настраиваем тестовую сцену и камеру для 2D.
- Размещаем временную площадку и простые тестовые объекты.
- Настраиваем сортировку слоёв и базовые коллайдеры, если они нужны.

**Чему учимся**
- GameObject и Component, Transform, Prefab, Scene, Sprite Renderer, Collider 2D, Rigidbody 2D.
- Отличие Scene View от Game View и как запускать/останавливать Play Mode.

**Критерии завершения**
- Сцена запускается без ошибок, тестовые объекты отображаются и взаимодействуют ожидаемым образом.
- Понимаем, какие компоненты отвечают за изображение, физику и положение объекта.

### Этап 2. Движение Хомяка и платформинг
**Статус: В работе**

**Что делаем**
- Создаём контролируемого персонажа с движением влево/вправо.
- Реализуем прыжок и двойной прыжок, обнаружение земли и проверяем поведение при падении за край.
- Проверяем неподвижные платформы и одностороннее прохождение сквозь платформу снизу; движущиеся платформы проверяем отдельно позже, если это потребуется прототипу.
- Уточняем поведение камеры на общей сцене для двух игроков, не создавая разделение экрана.

**Чему учимся**
- Основы C#: переменные, методы, условия, классы и ссылки на компоненты.
- Ввод, физика 2D, слои столкновений, проверка земли, Update и FixedUpdate — по мере необходимости.

**Критерии завершения**
- Персонаж надёжно движется, прыгает и выполняет двойной прыжок. Базовые движение, разворот и ограничение двумя прыжками проверены пользователем.
- Нельзя бесконечно прыгать в воздухе; проверены приземление, края и переход между двумя тестовыми платформами. Эти проверки подтверждены пользователем.
- Проверено поведение односторонних платформ: приземление сверху и прохождение снизу без застревания на боках.
- Обработка падения за пределы сцены пока не реализована: сейчас персонаж улетает вниз. Игровое последствие падения из README будет реализовано в соответствующем более позднем этапе; текущая проверка фиксирует только физическое поведение.
- Управление не зависит от частоты кадров неожиданным образом — требуется отдельная техническая проверка, поэтому критерий ещё не закрыт.

## Правила приоритета

- Сначала техническая основа и вертикальный срез, затем масштабирование контента.
- Не создавать семь уровней до проверки основного игрового цикла на первом.
- Не фиксировать окончательные цифры баланса до появления реальных боёв.
- Не добавлять не согласованные системы или функции только потому, что они типичны для жанра.
- Если фактический проект уже содержит часть этапа, сначала проверяем её и не повторяем работу.

## Текущий фокус

**Текущий фокус — этапы 0–2.** В этапах 1–2 созданы тестовая площадка и персонаж; пользователь подтвердил движение A/D, разворот спрайта, двойной прыжок W (не более двух прыжков до приземления), падение с края и маршрут между платформами. Для односторонних платформ включены `Used By Effector` и `Use One Way`.
