## 2. Фактическая база движения

Из `HamsterMovement.cs` и префабов:

- `moveSpeed = 15` — фактическое сериализованное значение в префабах; в коде default `5`, но он переопределён;
- `airAcceleration = 60`;
- `airDeceleration = 70`;
- `jumpForce = 10`;
- `maxJumps = 2`;
- `Rigidbody2D.gravityScale = 2.5`;
- гравитация проекта `-9.81`;
- `Rigidbody2D.mass = 1`;
- `linearDamping = 0`;
- `constraints = freeze rotation`;
- мирового коллайдера героя примерно `1.85 × 1.35`;
- `CollisionDetection = Continuous`.

Расчётно:

- одиночный прыжок поднимает примерно на `2.04` юнита;
- двойной прыжок в апексе — примерно на `4.08`;
- при горизонтальной скорости `15` дистанция одиночного прыжка около `12` юнитов;
- максимальная практическая дистанция двойного прыжка — около `20` юнитов при идеальном тайминге.

## 3. Character Feel — состояние и проблемы

### 3.1. Наземное движение

**Что есть:** скорость задаётся напрямую в `FixedUpdate`; на земле `linearVelocity.x = targetSpeed` мгновенно. В воздухе используется `MoveTowards` с `airAcceleration/airDeceleration`.

**Что работает:** управление отзывчивое, персонаж не «плывёт» после отпускания, скорость соответствует геометрии текущего уровня.

**Проблемы:**

- на земле нет разгона и торможения: скорость меняется скачком;
- нет отдельного поведения при смене направления;
- нет визуального наклона/крена;
- нет события начала/остановки движения для презентации;
- шаг атаки `StartAttack` фактически отменяется `FixedUpdate`, потому что `controlLocked` выставляет `moveInput = 0`, а ground-ветка сразу ставит скорость `0`;
- отсутствует ограничение максимальной скорости падения.

**Оценка:** база рабочая, но ощущение массы и направления слабое. Нужны acceleration/deceleration и отдельная логика разворота, не меняя общий принцип.

### 3.2. Прыжки

**Что есть:** двойной прыжок, сброс прыжков при контакте с землёй, `Grounded` по нормали контакта. Ввод читается в `Update` через `WasPressedThisFrame`.

**Проблемы:**

- нет coyote time: при сходе с платформы прыжок пропадает в тот же кадр;
- нет jump buffer: нажатие за несколько кадров до приземления теряется;
- нет variable jump height: высота всегда фиксированная;
- нет усиления гравитации падения;
- нет события приземления с силой удара;
- нет визуальной реакции на приземление;
- нет явной блокировки повторного срабатывания прыжка при удержании.

**Оценка:** прыжок функционален, но не прощает неточный ввод и не даёт контроля высоты. Это главный приоритет Character Feel.

### 3.3. Анимации движения

**Что есть:** Animator-параметры `IsMoving`, `IsGrounded`, `IsJumping`; состояния `Idle 0`, `HGo`, `HJump`, `HFall`, `FastPunch`, `Hook`, `Spin`, `JumpKick`, `Hurt`, `Charge`, `ChargedPunch`. Для Хомячихи аналогичные `HG*`.

**Сильные стороны:** полный набор базовых состояний, анимации уже подключены, события хитбокса в клипах есть.

**Проблемы:**

- нет отдельных состояний `Land`, `Turn`, `Skid`;
- переходы на землю/воздух имеют `TransitionDuration ≈ 0.25`, но при этом нет логики coyote/buffer;
- `IsMoving` определяется по вводу, а не по фактической скорости: при инерционном движении персонаж может визуально стоять, хотя физически скользит;
- `IsJumping = !isGrounded` не различает rising/falling, а `HFall`/`HJump` переключаются только через внутренние переходы контроллера;
- анимации деформации есть только в Idle/HGIdle; процедурной посадки нет.

**Оценка:** архитектура Animator рабочая, но презентации не хватает событий из физики и процедурного слоя.

### 3.4. Масса и деформации

**Что есть:** некоторые клипы имеют squash/stretch через `m_LocalScale` (`Idle`, `HGIdle`).

**Проблемы:** нет сжатия при посадке, нет наклона при разгоне/торможении, нет визуального отличия сильного приземления от слабого.

**Ограничение:** Animator анимирует `Visual.localScale.x/y`, поэтому процедурный слой должен либо работать в `LateUpdate`, либо не трогать scale постоянно, иначе конфликтует с клипами. Позиция и rotation у `Visual` анимациями не управляются — их можно использовать безопасно.

### 3.5. Кооператив

**Что есть:** `GameSession` отключает одного героя в соло, `HamsterMovement.SetPartner` ограничивает горизонтальную/вертикальную дистанцию, `CameraFollow` расширяет orthographic size до 15.

**Проблемы:** изменения acceleration/jump должны сохранить ограничения дистанции. Нельзя привязывать jump buffer к глобальному времени одного игрока или делать общий визуальный контроллер на двоих.

**Оценка:** архитектура кооператива пригодна; новые системы должны быть per-player и не использовать статические общие состояния, кроме разрешённых HitStop/CameraShake.

## 4. Combat Feel — состояние и проблемы

### 4.1. Атака и хитбокс

**Что есть:**

- `AttackController` управляет комбо из 3 ударов;
- Animation Events включают/выключают `Hitbox`;
- `Hitbox` использует `OverlapBoxAll`, хранит `HashSet<Health>` и наносит один урон на активацию;
- `HitData` — ScriptableObject с уроном, knockback, hitStop, hitStun, launchVelocity, размером и смещением хитбокса.

**Сильные стороны:** урон и активация хитбокса уже привязаны к анимационным событиям; это правильная основа, которую не нужно переписывать.

**Проблемы:**

- `Hitbox` передаёт `hitPoint` как центр хитбокса, а не фактическую точку контакта;
- `Hitbox` всегда вызывает `CameraFollow.Shake(0.2f, 0.16f)` и всегда создаёт одинаковый spark;
- `DamageInfo` не содержит веса удара, поэтому реакция не знает, лёгкий это удар или тяжёлый;
- `HitData` не содержит параметров камеры/искры/типа реакции;
- `attackDurations/cancelTimes` в префабах (`0.28/0.24/0.62`) немного длиннее клипов (`0.264/0.225/0.600`), а `airDuration = 0.3` длиннее клипа `0.225`;
- наземный шаг атаки обнуляется движением;
- нет отдельного события «попадание» для звука/системы мониторинга.

**Оценка:** логика попадания есть, но обратная связь и дифференциация ударов слабые.

### 4.2. Реакция врагов

**Что есть:** `HitReaction` слушает `Health.Damaged`, запускает белую вспышку и увеличивает визуал на `1.08`, затем `ShortKnockback`: фиксированная горизонтальная скорость `5` на `0.18 с`.

**Проблемы:**

- `DamageInfo.launchVelocity` полностью игнорируется;
- сила/направление удара не учитываются: тяжёлый `Spin` и лёгкий `FastPunch` дают одинаковую физическую реакцию;
- нет вертикального подскока/полёта;
- нет визуального наклона;
- нет landing/recovery;
- `IsLaunched` блокирует хитбокс только до конца короткого корутина;
- AI `HurtRoutine` может вернуть Idle, пока враг ещё летит;
- `Health` сначала применяет собственный knockback, затем `HitReaction` его перезаписывает — две системы конкурируют за скорость.

**Оценка:** это главное слабое место Combat Feel. Нужно переписать только `HitReaction` и передать ему вес удара через `DamageInfo`, не меняя `Health`-конвейер.

### 4.3. Игрок и получение урона

**Что есть:** `Health` уменьшает HP, применяет knockback, `PlayerCombatState` запускает Hurt-анимацию и блокирует управление на `hurtDuration = 0.28`.

**Проблемы:**

- у игроков `invulnerabilityAfterHit = 0` — несколько врагов могут бесконечно прерывать игрока;
- нет компонента `HitReaction` на героях;
- нет визуального мерцания i-frames;
- нет отдельного контроля отброса по высоте;
- `PlayerCombatState` не учитывает длительность физического hitstun;
- повторное попадание перезапускает Hurt без окна защиты.

**Оценка:** система здоровья рабочая, но feedback и защита от цепочки прерываний неполные.

### 4.4. Hit Stop и камера

**Что есть:** `HitStop.Play(duration)` останавливает `Time.timeScale`; `CameraFollow.Shake` задаёт случайное смещение. Оба уже централизованы.

**Проблемы:**

- HitStop длительность берётся из `HitData`, но камера всегда одинаковая;
- нет различия между попаданием по врагу и получением урона игроком;
- нет проверки, что эффект происходит синхронно с фактическим уроном (спарк и звук не имеют контакта с `Health.Damaged`);
- HitStop работает через `Time.timeScale = 0`, что останавливает и физику, и анимации; это допустимо, но нужно сохранять синхронизацию эффектов, использующих unscaled time.

### 4.5. Заряженная атака

**Что есть:** накопление `charge01`, `ChargeVFXController`, `Burst`, рывок `dashSpeed = 30`, `dashDuration = 0.22`, код-управляемый хитбокс во время рывка.

**Проблемы:**

- хитбокс во время рывка активен весь рывок и может наносить урон всем целям в зоне независимо от визуального контакта;
- при столкновении со стеной рывок обрывается, но эффект попадания/камера не связаны с моментом контакта;
- нет отдельного визуального состояния попадания заряженного удара (сейчас только общий spark/камера);
- завершение рывка и lock работают, но нужен более контрастный impact.

**Оценка:** механика сохраняется, нужен усиленный impact-профиль и более строгая синхронизация.

### 4.6. VFX и звук

**Что есть:** `HitSpark`, `FireTrail`, `ChargeVFX`, `DizzyStars`, `ReviveBubble`, `GirlLightning`, `ThrowImpactVFX`, `HitStop`.

**Чего нет:**

- пыли приземления;
- разных искр/вспышек по весу удара;
- визуального мерцания i-frames;
- звуковых файлов (`Assets/Audio/` пуста);
- AudioSource/audio hook-ов в боевых событиях.

**Оценка:** визуальные эффекты можно улучшить без новых обязательных спрайтов; звук — отдельный ресурсный блок, который нельзя честно закрыть без аудиоассетов.

### 4.7. Синхронизация анимации и физики

**Факт:** хитбокс уже включается Animation Event внутри клипа, поэтому текущая схема синхронизации в основе правильная.

**Что нужно исправить:**

- привести `attackDurations` к фактическим длинам клипов или брать длину из `Animator`/`AnimationClip`;
- привести `airDuration` к `0.225`;
- передать в `DamageInfo` тип удара и точку контакта;
- отделить воздействие на физику от анимационного state;
- обеспечить, чтобы при прерывании атаки хитбокс всегда деактивировался.

## 5. Что можно улучшить без переписывания

- `HamsterMovement` — добавить acceleration/deceleration, coyote, buffer, variable jump, fall gravity, landing events.
- `HitReaction` — заменить фиксированный `ShortKnockback` на профили Light/Medium/Heavy/Launch.
- `HitData` / `DamageInfo` — добавить вес удара и параметры искры/камеры.
- `Hitbox` — передавать точку контакта и параметры impact.
- `Health` — добавить i-frames и публичное состояние неуязвимости.
- `PlayerCombatState` — согласовать hurt-анимацию с hitstun/i-frames.
- `HitSpark` — поддержать масштаб/цвет/направление.
- `CameraFollow` — использовать параметры shake из impact, не менять принцип работы.
- `HyenaAI` — не возвращать Idle во время полёта/стаггера.

## 6. Что требует новых компонентов

1. `CharacterMotionVisual` — процедурный наклон, squash при приземлении, пыль, визуальная обратная связь движения.
2. Расширенный профиль impact в `HitData`/`DamageInfo`.
3. Расширенный `HitReaction` с контролируемым launch/recovery.
4. `HitFeedback`-хук для звука (без аудиоресурсов сейчас, чтобы не вставлять случайные звуки).

## 7. Архитектурный вердикт

Архитектура пригодна для улучшения без переписывания:

- движение и прыжки уже собраны в `HamsterMovement`;
- хитбокс и урон уже разделены на `Hitbox` → `Health` → `HitReaction`;
- `HitStop` и `CameraShake` уже централизованы;
- Animation Events уже используются;
- ScriptableObject `HitData` уже является правильной точкой для параметров удара;
- HUD, пауза, кооператив и камера не требуют замены.

Необходимо только расширить существующие точки и добавить один визуальный компонент персонажа. Полная замена `HamsterMovement`, `AttackController`, `Health` или `HitReaction` архитектурно не требуется.

## 8. Приоритеты реализации

1. **Реакция на удар** — сейчас самый заметный дефект.
2. **Приземление и разворот** — сильнее всего влияют на ощущение массы.
3. **Синхронизация хитбокса с анимацией и точкой контакта**.
4. **i-frames и визуальная неуязвимость игрока**.
5. **Разные VFX/камера по весу удара**.
6. **Звук** — после появления аудиоресурсов.
